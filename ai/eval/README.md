# Argument Judge evaluation

The Argument Judge (docs/ARCHITECTURE.md §4.5) is only as trustworthy as its calibration. This folder holds the gold set it is scored against.

## Gold set format

`gold.jsonl`, one item per line (see `gold.example.jsonl`):

| Field | Meaning |
|---|---|
| `id` | Stable identifier |
| `passage`, `stem`, `choices` | The argument, question and five options A–E, in our own words |
| `subtype` | `weaken`, `strengthen` or `assumption` (the sub-types the judge gates today) |
| `gold_label` | The answer a human adjudicator settled on |
| `adjudicator`, `notes` | Who decided and why, including which trap each strong distractor sets |

Only original items go in the gold set: our own writing or items generated by Questionize and then adjudicated by a person. Never copy items from published test-prep material.

## Running

```bash
cd ai
python -m questionize.eval_judge eval/gold.jsonl --out eval/report.json
```

This calls the configured judge models (it needs a provider key in `ai/.env`) and prints accuracy, the gate pass rate, the mean margin and the expected calibration error. Results are published per judge version.

## E1: solving and explaining official-style items

### Building the dataset from a scan

A prep book you own whose answer section prints one question per page (passage, options, key and explanation) can be imported directly instead of snapped item by item:

```bash
cd ai && pip install -r requirements-research.txt     # on a Mac this includes Apple Vision OCR
python -m questionize.import_scan ~/private/og.pdf --pages 520-640 --book "Official Guide" --out ~/private/official-cr-v1.json
```

An on-device OCR engine reads each page into lines (`--ocr apple` on macOS, `tesseract` elsewhere; `--ocr-only` checks it). By default the layout is found by rules, with no model call: the book's answer section reads number and passage, stem, options (A)-(E), a reasoning-type banner, the explanation and "The correct answer is X.", and questions may run across pages; running headers and page numbers are dropped and the sub-type is guessed from the stem. `--layout model` sends each page's OCR text to the primary model instead, which returns the passage, stem, options, key, the book's explanation split by option, the sub-type and a trap tag per option; its copy is checked word by word against the OCR text (flag `not_as_printed` under 97%) and its key against the printed one. Items with a missing number, option or field are flagged; fix them against the page in the JSON and set `"flagged": false`. E1 skips them until then. The output quotes the book, so the script refuses a path inside the repository.

### Running

Protocol: `research/protocols/E1-solve-and-explain.md`. The dataset is a curator's export from the web app (Me → Research dataset): item text from the curator's device plus the book's key letters. Keep it outside the repository.

```bash
cd ai
python -m questionize.eval_e1 ~/private/official-cr-v1.json --conditions B0,B1,B2
```

It writes a run directory under `~/questionize-research/runs/<run_id>/` (`--out` to change):

| File | Contents |
|---|---|
| `manifest.json` | Run id, protocol version, git SHA, prompts hash, models, judge version, seed, dataset id and hash, exclusions |
| `results.jsonl` | One line per item and condition: answer, key, confidence, explanation, calls, debate rounds and judge readings |
| `summary.json` | Accuracy with Wilson 95% interval, calibration error, calls; for B1/B2, McNemar against B0 and a paired bootstrap interval for the gain |
| `rating_sheet.csv` | Explanations shuffled with the condition hidden, for blind rating (correct / partly / wrong) |
| `rating_key.csv` | Joins rating ids back to items and conditions after rating |

It appends one line with identifiers and the summary (no item text, no paths) to `research/ledger.jsonl`; commit that line. With the solver pointed at the same model as the primary, B2 is reported as B2′.

## Before and after learning (E4 → E1 → memory → E1+M)

```bash
cd ai
# 1. Capture the book twice: layout rules, and the model structuring the OCR text (E4)
python -m questionize.import_scan ~/private/og.pdf --pages 1-N --out ~/private/og-rules.json
python -m questionize.import_scan ~/private/og.pdf --pages 1-N --layout model --out ~/private/og-model.json
# 2. Compare them; agreed items become the verified dataset, split 60/40 into train and test
python -m questionize.eval_e4 ~/private/og-rules.json ~/private/og-model.json --out ~/private/official-cr-v1.json
# 3. Baseline: the model as it is, on the test split
python -m questionize.eval_e1 ~/private/official-cr-v1.json --split test --conditions B0,B1
# 4. Learn: lessons from the train split, checked against the key and explanation
python -m questionize.memory ~/private/official-cr-v1.json --out ~/questionize-research/memory/cr-v1.json
# 5. After: the same conditions with the memory, paired with the baseline run
python -m questionize.eval_e1 ~/private/official-cr-v1.json --split test --conditions B0,B1 \
    --memory ~/questionize-research/memory/cr-v1.json --baseline ~/questionize-research/runs/<baseline run id>
# 6. Scoreboard
python -m questionize.scoreboard   # SCOREBOARD.md and each capability's HISTORY.md
```
