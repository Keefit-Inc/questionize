# E15 v1 — GMAT CR failure closure and expanded private source evaluation

Registered 2026-10-30 (Los Angeles), before new generation calls. Objective: reduce actual solving errors, close the known official failures, and evaluate as many eligible GMAT-labelled sources as the bounded budget allows. No guarantee of universal 100%, no question-generation or learner-benefit claim.

## Data roles

The 124 previously used official OG records and 155 E14 records are exposed development/regression data. Earlier results remain immutable. Source-key-only GMAT-labelled records from the private user compilation are mechanically checked and deduplicated against all exposed sources before partitioning. Quarantine ambiguous key mapping and malformed records; exclude exact/near shared stimuli. Preserve source origins and original keys. The compilation's self-declared exam and supplied answers are not independently adjudicated official GMAC gold.

Freeze source-test-group partitions before candidate selection: roughly a quarter of eligible compilation test groups for development, the remainder for untouched final confirmation. Keep all LSAT records unused. Publish only quantities, hashes, source-confidence strata and aggregate results. No raw item or local storage path goes into Git or the server research feed. Source material is used in Standard Meta inference with `store=false`, never Contributor mode; private preparation restrictions do not imply a redistribution licence.

## Candidate development

First compare the two previously failed OG cases under Spark medium, Spark high, a mechanism-guided Spark high Solver, and a separately labelled Wonder high condition. Use source keys only after answering. Fix a bounded set of general procedures using exposed development evidence: separate stated facts from invented links; distinguish strengthening from deductive sufficiency; represent argument-level claims separately from internal causal wording; align ratios, counts and denominators. Procedure payloads and lineage remain private. They must not contain question-specific answer rules.

The mechanism Solver returns a concise, source-anchored task and option audit, plus an optional numeric argument description. A bounded arithmetic checker can produce a counterexample for an invalid rate-to-count inference. Its findings are conditional on the source-to-variable mapping, not a certification of the entire question. No model-generated executable code runs. A tool-informed repair is a separate metered call; if it fails, retain a completed first answer and expose the failed repair separately. An unrestricted same-model critic cannot automatically overturn answers.

Use the OG development cohort and separately frozen compilation development groups to select one candidate. Model changes, effort changes and procedure/tool changes are distinct conditions, never all credited to memory. Check known failures again and retain prior correct cases. Freeze candidate model, effort, procedure/hash, budget and selection rule before untouched confirmation. If no candidate beats the baseline under comparable conditions, record that outcome rather than manufacture a gain.

## Resources and completeness

Standard Meta models and verified token prices: Spark 1.3 $1.25/M input, $0.15/M cached input, $4.25/M output; Wonder 1.0 $4/M input, $0.20/M cached input, $20/M output. Reviewed 2026-10-30 at https://dev.meta.ai/docs/pricing-rate-limits . Hidden reasoning is output usage. Explicit effort, no silent generation retries, bounded concurrency (at most six items), no external tools beyond the bounded arithmetic checker.

Total normalised token-price spending has a **$30 envelope**, including development. Reserve a request allowance before dispatch so concurrent calls cannot overdraw the remaining envelope. Default Spark item envelope $0.06; Wonder development/probe envelope $0.15. Freeze the final condition's envelope after development. Both final arms receive the same per-item spending ceiling; actual spending and training/selection costs are reported separately. If the budget stops evaluation, disclose evaluated versus registered versus unattempted counts and compare only the same attempted prefix. Missing usage invalidates complete cost accounting; do not count it as free inference.

## Outcomes and gates

Report by data role and confidence stratum: correct/registered/evaluated, source-key agreement, Wilson intervals, paired gains/losses, error categories, repair rescue/harm, tokens, estimated billed and normalised cost, and latency. Previously exposed official regression closure is a development result, never untouched generalisation. Known 155 E14 items are not relabelled, dropped or reported as fresh after this optimisation.

Select on development only. Run the frozen candidate and baseline once on untouched final membership; do not tune on final errors and call the same data fresh again. 100% on a verified fixed regression set is a concrete closure goal, not proof of universal accuracy. Source ambiguity review remains separate from scoring. No automatic production adoption merely for a higher point estimate. Require no new official regression, operational integrity and a fresh paired benefit before considering a release; keep an unchanged service on failed/held evidence. Fine-tuning remains a possible later candidate class, not something performed by this inference study.
