## Input recovery and verification

The original PDF and v1/v2 datasets remain private and immutable. v3 SHA-256: `c164092aebcea3f504a3bb428db68eac905f12d669d0e892123c9e19f0c90dc3`. The original 70 train / 39 test membership remains; 15 flagged captures remain excluded. There are 124 captured records in total.

Targeted visual source inspection restored nine emphasis-dependent stimuli, seventeen printed identifiers, five omitted stimulus lines and one truncated reference-rationale ending. This affected 28 distinct records across the two repair manifests. Eight of the eleven original structure-classified items need emphasis; three do not. Another emphasis item had been misclassified as evaluate.

Apple Vision and Tesseract outputs were retained for 125 content pages. Tesseract independently recovered matching printed keys for 123/124 records; the remaining key was checked directly against the rendered source. The stimulus comparison aligned 113/124 regions automatically. Eleven regions remain separately reviewable because prefix/label OCR did not align; this is not a statement that they are wrong. Detected omitted lines were checked visually. One reordered Tesseract text block required order-aware triage, not a change to source meaning.

This is mechanical validation, dual-OCR comparison and targeted agent visual inspection. It is **not** independent human certification of every character, a measured character-error-rate result, or complete C1 solvability-equivalence validation. The importer now flags unsupported emphasis and suspicious truncated stimuli instead of approving them from one-way word agreement alone. Private `source_crosscheck` reports contain per-page hashes and review candidates; public exports exclude source text.

The first full evaluation and E10 exposed remaining source/fixture problems. They were not discarded. The v2 revision was committed before its inference. Each new run archives an exact private Python source snapshot because its implementation was evaluated from a dirty working tree; the manifest records the registration commit and composite source hash. Final repository commits can contain subsequent reporting changes, so a commit ID alone is not the evaluated source snapshot.

This development set informed the repairs and policy. Published questions may have appeared in pretraining. These scores do not establish 99.9% population accuracy, unseen generalization, a causal improvement over E1's different inputs, or correctness of explanations. C3.2 remains unmeasured pending blind human ratings. The existing policy release remains distinct from the separately versioned deterministic integrity guard; the console reports the running service's observed guard version.

## Reproduce

From `ai/`, with private artifacts and the configured Meta account:

```sh
python -m questionize.capture_audit PRIVATE_V2 --repairs PRIVATE_REPAIRS --out NEW_PRIVATE_V3
python -m questionize.source_crosscheck PRIVATE_V3 --cache PRIVATE_OCR_CACHE --out NEW_PRIVATE_REPORT
python -m questionize.eval_reliability PRIVATE_V3 --protocol E9 --version 2
python -m questionize.publish_evidence PRIVATE_RUN_DIRECTORY
python -m questionize.scoreboard
```

Do not repeat paid inference to select a better score. Preserve failed and null outcomes. The exact protocol is [E9 v2](../protocols/E9-repaired-input-reliability-v2.md); literature connections are in [the evidence registry](../evidence-map.json).
