# E1 v2: CR solving and explanation — initial baseline and memory comparison

## Outcome

The 39-item test evaluation found **no increase in solving accuracy** from the verification loop or the frozen memory. B0, B1, B0+M and B1+M each answered 37/39 items correctly (94.87%; Wilson 95% interval 83.11%–98.58%). These are provisional benchmark observations: a subsequent capture and method audit identified missing emphasis spans and an incorrectly applied verification objective. They are not evidence that the complete solve-and-explain capability has been validated.

Human explanation ratings have not been collected. C3.2 therefore remains unmeasured; solving accuracy is not an explanation-quality score. The five-item memory trial was an execution check, with a baseline already at 5/5, and does not establish an improvement.

## Data and conditions

Dataset `official-cr-v1` (hash `f8478fddd1285fd5`) contains 124 captured CR items. Fifteen flagged captures were excluded, leaving 70 train and 39 test items. Official item text, scans, per-item model outputs and rating sheets remain private.

The memory was learned only from the train split: 70 reflections consolidated into 48 rules across eight subtypes, hash `0a11573f6e4bfdd8`. The model answered 66/70 train items correctly before seeing the key and explanation. This is reflection and prompt memory, not a change to model weights. The same memory artifact was used for the trial and full memory evaluation.

- **B0:** one answer-and-explanation call.
- **B1:** blind solver, an Argument Judge for applicable subtypes, then an explanation of the settled answer.
- **+M:** the subtype's rules are added to the solver and explainer prompts. The Judge itself does not receive this memory.

All four conditions use `muse-spark-1.3`. The local random seed is 7; this does not establish deterministic provider-side inference. Each condition was run once, so stochastic model and Judge variation remains a limitation.

## Qualifications found during the audit

1. **Required formatting was lost.** All 11 usable structure/boldface captures have no explicit emphasis-span markers: seven train and four test items. Audited wrong answers show models assuming different target spans. High OCR text agreement did not certify preservation of the information needed to answer these questions. Consequently, C1 capture errors are mixed into the C3 evaluation, and the learned structure memory also needs review after capture repair.
2. **The verification objective can be wrong.** In an audited EXCEPT item, the B1 solver was correct and the subtype-based Judge changed it to an incorrect answer. High ranking stability measures agreement under the chosen objective; it does not prove that the objective matches the question. The same incorrect override occurred in the full memory condition.
3. **Explanation disagreement and confidence are insufficiently reconciled.** The audited explanation object did not flag a disagreement even though its prose challenged the settled answer. In addition, E1 v2 retains the original solver confidence after a Judge override. The reported B1 ECE is therefore not a validated measure of confidence in the final decision.

An exploratory, post-hoc diagnostic excluding the entire four-item structure category leaves 35 items: B0 and B0+M are 35/35, while B1 and B1+M are 34/35. This does not replace the preregistered 39-item result and is not an independently confirmed finding.

The composite prompt/code hash differs between the baseline (`2628088f56acdece`) and full memory run (`70c622513cd8a28e`). The recorded source diff changes photo-reader instructions; the E1 runner, Judge, levels and scan importer are unchanged between these recorded versions. The mismatch remains visible rather than being silently treated as identical provenance. The protocol's v2 prose change-log date is inconsistent with its Git history: the v2 implementation was committed on October 29 before the baseline run. The committed runner version and ledger timestamps identify the evaluated method.

Published practice-book items may already be represented in a model's pretraining. A held-out split within this local dataset does not establish that the model has never seen the official items.

## Next version

Preserve these runs and their null outcome. Before another quality claim:

1. Restore and verify the required target spans in every affected train and test capture; version the dataset and retain the original artifacts and split provenance.
2. Match verification to the question's actual operator and target. An inapplicable or unsupported Judge must abstain from overriding the solver.
3. Reconcile explanation objections with the final answer, and define confidence for the final decision before using calibration as evidence.
4. Rebuild the affected memory from verified train inputs and evaluate the revised method under a new protocol version. Record that fixes were informed by this development set and use an independent benchmark before claiming generalization.
5. Collect blind human explanation ratings, then test E2 with explicit, supported question designs. The current 48 solving rules are not yet a validated generation memory.

## Follow-up capture clarification (E9, 2026-10-30)

The later source audit found that eight of the eleven structure-classified items actually require emphasis; three ask about argumentative strategy without marked spans. One additional emphasis-dependent item was misclassified as evaluate. E9 restored nine emphasis items, seventeen identifiers, five omitted stimulus lines and one reference-rationale ending in separate private dataset versions. Original E1 runs and their qualifications are retained. These follow-up repairs do not retroactively validate the original text. See [E9](E9.md).
