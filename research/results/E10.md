# E10: constructed defect rejection and control acceptance

## Result

The full v2 suite rejected **26/26 constructed defects** and accepted **7/8 reference controls**. The existing blind-Solver/Critic gate and the same gate with deterministic integrity checks made identical acceptance decisions. There is **no measured accuracy gain** from the integrity guard in this suite. Its value is rejecting ten exact structural defects before any model call and preventing inconsistent future model acceptance of those specific defects.

Run `20261030T200529Z-e10-6dd8bb`, E10 v2, `muse-spark-1.3`, 34/34 complete, zero execution failures, 52 logical model calls. Cases share eight parent items. Do not calculate an independent-sample confidence interval across these mutations or infer a population defect rate.

The rejected reference control was a repaired boldface problem: the blind Solver selected a different letter from the reference key. It had answered this item correctly in E9. This shows that one successful temperature-zero run does not certify deterministic or 99.9% reliability. The gate withheld the candidate instead of publishing it under the wrong answer. Control acceptance therefore remains 7/8, not silently rounded to perfect.

## What was actually tested

This uses the production verification implementation with zero revisions, article-copy checks disabled for these reference inputs, and the Argument Judge disabled. It isolates the blind Solver/Critic gate. E9 evaluates the Argument Judge separately. The same model outputs serve both gate conditions; the guarded condition short-circuits exact duplicate choices and absent required spans. Incorrect keys follow the reference key plus an explicit mutation, not AI consensus. The explanation mutation explicitly contradicts the proposed answer; it does not cover every subtly misleading explanation.

The controls carry source-extracted option rationales; trap tags remain model-derived metadata. Private reference explanations are supplied as candidate explanations to the Critic, never as gold information to the blind Solver. The production guard is `integrity-0.1`. It adds no normal-control rejection in this suite and passes the registered structural release contract, subject to offline checks and actual deployment verification. It does not certify broad automatic-publication quality.

## Earlier fixture limitations retained

The v1 full run `20261030T195124Z-e10-ed8ba8` rejected all 26 defects and accepted 6/8 controls. Inspection found a truncated stimulus, a truncated source rationale and placeholder option rationales. Those controls were insufficient to isolate semantic false rejection. v2 was registered before new inference, used the same eight parents and mutation kinds on v3 capture, and restored actual rationales. The changed control inputs and model variation prevent attributing the acceptance difference to a new verification method.

Smoke runs `20261030T194544Z-e10-4277b0` (v1) and `20261030T200342Z-e10-fca10d` (v2) each completed five cases and rejected four constructed defects while accepting one control. All runs remain in the ledger. Exact evaluated source snapshots and per-case outputs remain private; no book wording, source explanations, private IDs or learner data are in this report.

The next substantive gap is independently adjudicated, subtle ambiguity and incorrect reasoning that is not an obvious label contradiction. Those items need reference evidence and review; additional model votes cannot manufacture gold labels. There is no learner-growth result or human explanation-quality score here.
